## 0. Principio rector

EFESTUM no debe construirse como una marca “mitológica” ni como una marca “futurista” genérica.

La mitología funciona como una capa cultural y conceptual. La tecnología, la ingeniería y la precisión son la prueba tangible de la marca.

La lógica del sistema es:

> **La forja es el lenguaje madre.**  
> **La mitología es el matiz.**  
> **La tecnología es la prueba.**  
> **La precisión es la promesa.**

La marca debe poder hablar de software, inteligencia artificial, automatización, infraestructura, datos, integraciones, productos y sistemas empresariales sin depender de la presencia de una escultura o de una referencia mitológica explícita.

# 2. SISTEMA DE TONO Y FRASES POR CATEGORÍA

## 2.1 Personalidad verbal

Efestum debe sonar:

- preciso
- sobrio
- técnico
- seguro
- ambicioso
- estructurado
- inteligente
- contemporáneo

Efestum no debe sonar:

- exageradamente épico
- fantasioso
- agresivo
- adolescente
- gamer
- “futurista” genérico
- lleno de clichés sobre IA
- excesivamente mitológico

---

## 2.2 Regla de construcción de mensajes

La fórmula recomendada es:

**idea empresarial real + tensión conceptual + lenguaje de Efestum**

Ejemplo:

Problema real: falta de visibilidad de datos.  
Tensión conceptual: operar sin ver.  
Lenguaje Efestum:

> **DOMINAMOS LO QUE NADIE VE.**  
> Infraestructura, datos y monitoreo en un solo sistema.

La frase conceptual atrae.  
La segunda línea explica.

Nunca debe dejarse una metáfora sola si el contexto comercial necesita claridad.

## 3.1 Regla de uso de los arquetipos

Los arquetipos pueden utilizarse en tres niveles:

### Nivel 1 — Invisible

Solo se usa el concepto.

Ejemplo:

> **DATOS CLAROS. DECISIONES PRECISAS.**

No se menciona a Apolo ni se muestra una estatua.

### Nivel 2 — Metafórico

Se utiliza una frase asociada al territorio.

Ejemplo:

> **LUZ SOBRE TUS DATOS.**

Puede acompañarse con dashboard o interfaz.

### Nivel 3 — Hero

Se utiliza la escultura del dios correspondiente.

Ejemplo:

Poseidón + dashboard + frase:

> **MAREAS DE INFORMACIÓN. CONTROL TOTAL.**

Este nivel debe utilizarse con menor frecuencia.

---

## 3.2 Frecuencia recomendada

Para evitar saturación:

- **60 %** tecnología real: dispositivos, UI, dashboards, apps, sistemas, monitores
- **25 %** sistema gráfico puro: mármol digital, tipografía, mensajes, diagramas
- **15 %** esculturas del panteón griego

No es una regla matemática rígida, sino una guía para mantener el recurso mitológico especial.

# 4. MANUAL DE USO VISUAL Y VERBAL

## 4.1 Principio visual

Efestum combina dos capas:

### Capa clásica

Representa:

- permanencia
- dominio técnico
- cultura
- oficio
- estructura

### Capa digital

Representa:

- sistemas

- tecnología
- escalabilidad

La identidad no debe parecer una “marca de dioses griegos”.

Debe parecer una empresa tecnológica que utiliza referencias clásicas como una capa de significado.

---

## 4.2 Mármol Digital

### Definición

El Mármol Digital es una textura propietaria construida a partir de:

- fondo blanco o gris extremadamente claro
- grid técnico
- matriz de puntos
- zonas de densidad variable
- espacio negativo

### No utilizar

- vetas de mármol
- grietas
- texturas pétreas naturalistas
- columnas decorativas dentro de la textura
- grecas griegas
- laureles
- patrones clásicos ornamentales

El nombre “Mármol Digital” describe el concepto, no una simulación literal de piedra.

---

## 4.3 Uso del rojo

**Rojo oficial:** `#E40800`

El rojo representa conceptualmente la energía de la forja, pero nunca debe mostrarse literalmente como fuego.

### El rojo sí puede aparecer en:

- una palabra clave
- un filete corto
- pequeños indicadores
- estados activos en UI
- puntos de datos
- iconos secundarios
- CTA puntuales
- microdetalles de navegación

### El rojo no debe:

- dominar más de una parte importante de la composición
- convertirse en grandes fondos salvo aplicaciones excepcionales
- colorear esculturas completas
- convertirse en efectos de fuego
- utilizarse como glow excesivo
- hacer que la marca parezca agresiva

### Regla práctica

En una pieza normal, elegir **uno o dos usos principales de rojo**, no todos a la vez.

Ejemplo correcto:

**MAREAS DE INFORMACIÓN, CONTROL TOTAL**

Solo **INFORMACIÓN** en rojo + pequeños indicadores del dashboard.

---

## 4.4 Uso de esculturas

### Sí

Utilizar únicamente figuras claramente pertenecientes al universo clásico grecorromano y, cuando se identifique un personaje, preferentemente dioses del panteón griego vinculados al concepto de la pieza.

### Recomendado para

- campañas hero
- espectaculares
- portadas
- brand films
- presentaciones institucionales
- lanzamientos
- piezas editoriales

### Evitar en

- cada post
- cada banner
- todos los módulos web
- cada pantalla de producto
- dashboards funcionales
- piezas demasiado técnicas

Las esculturas son un **acento conceptual de alto impacto**, no un fondo obligatorio.

# Checklist de consistencia

Antes de aprobar una pieza Efestum:

- [ ] ¿Se entiende el beneficio tecnológico aunque eliminemos la referencia mitológica?
- [ ] ¿La pieza demuestra software, IA, datos, infraestructura o sistemas?
- [ ] ¿La mitología aporta significado en lugar de decoración?
- [ ] ¿El rojo es un acento y no el protagonista?
- [ ] ¿El Mármol Digital conserva únicamente grid + puntos + espacio negativo?
- [ ] ¿La composición mantiene suficiente aire?
- [ ] ¿La frase principal es breve?
- [ ] ¿El tono se siente seguro, preciso y sobrio?
- [ ] ¿Estamos evitando clichés tecnológicos?
- [ ] ¿La escultura realmente es necesaria en esta pieza?
- [ ] ¿Si aparece un dios, existe una relación conceptual con el mensaje?
- [ ] ¿La marca sigue pareciendo una empresa de software e IA antes que una marca mitológica?
