# EFESTUM — Skill para posts con dioses griegos
**Versión:** 2.0  
**Uso:** generación automática de piezas de redes sociales con esculturas de dioses griegos + tecnología contemporánea, manteniendo consistencia de marca EFESTUM.

---

## 1. Objetivo

Crear posts premium para EFESTUM donde la mitología funcione como **metáfora visual de ingeniería**, no como tema decorativo.

La pieza debe sentirse como una marca de software e inteligencia artificial de alto nivel:

- sobria
- precisa
- contemporánea
- corporativa
- tecnológica
- memorable
- con referencias clásicas controladas

La imagen debe poder entenderse aunque el espectador no identifique al dios por nombre.

---

## 2. Principio central

> **Escultura clásica + tecnología contemporánea + mensaje de ingeniería.**

El dios NO posa como personaje de fantasía.  
Debe parecer una **escultura de museo trasladada a un contexto tecnológico actual**.

Cuando aparezca un dios, debe estar **usando activamente un dispositivo moderno** relacionado con el mensaje:

- laptop
- tablet
- smartphone
- monitor
- workstation
- dashboard
- panel de datos

Nunca colocar un dispositivo solo como accesorio decorativo.

---

# 3. Reglas de marca no negociables

## Logotipo

- Usar preferentemente el **logo horizontal oficial de EFESTUM**.
- Respetar exactamente símbolo, proporciones y wordmark.
- No redibujar el logo.
- No deformar.
- No rotar.
- No añadir “SYSTEMS”.
- No separar el isotipo del wordmark en el encabezado principal.
- En los dispositivos puede aparecer únicamente el **isotipo oficial** como marca de hardware.

## Tipografía

### Títulos
Usar **EFESTUM Display**, con el mismo lenguaje geométrico del logotipo.

### Texto secundario
Usar **Rubik**.

### Labels
- Rubik
- uppercase
- tracking amplio
- tamaño pequeño
- nunca deben competir con el titular

## Color

Paleta oficial:

- Ink: `#0A0A0A`
- White: `#FFFFFF`
- Paper: `#F4F4F4`
- Accent: `#E60004`
- Muted: `#8A8A8A`
- Rule light: `#D8D8D8`

Regla principal:

> El rojo es señal, no relleno.

Máximo recomendado: **5% de la superficie visual**.

Usos correctos del rojo:

- Filo de Forja
- una palabra clave
- un dato
- un punto final
- pequeños indicadores UI
- CTA mínimo

No usar rojo como gran bloque de fondo.

---

# 4. Mármol Digital

“Mármol Digital” NO significa mármol real.

Debe construirse con:

- fondo blanco / paper
- grid técnico muy tenue
- campos de puntos
- líneas de ingeniería sutiles
- amplio espacio negativo
- textura limpia y monocromática

Evitar:

- vetas de mármol reales
- piedra envejecida
- grietas
- columnas decorativas
- grecas
- laureles gráficos
- ornamentos clásicos
- dorado
- cyberpunk
- neón

---

# 5. Dirección de las esculturas

## Material

La figura debe conservar claramente apariencia de:

- mármol blanco
- escultura de museo
- textura mineral sutil
- acabado mate
- luz suave
- detalle escultórico fino

No convertirla en humano real.

## Expresión

La expresión debe ser:

- serena
- divina
- segura
- contemplativa
- ligeramente satisfecha
- contenida

No usar:

- sonrisa amplia
- alegría evidente
- gesto comercial
- enojo
- agresividad
- ceño exagerado
- expresión malvada
- pose de superhéroe

**Objetivo emocional:**  
“dominio tranquilo”, no “felicidad”.

## Pose

Variar entre piezas:

- frontal
- 3/4 izquierdo
- 3/4 derecho
- contrapicado leve
- sentado
- de pie
- busto parcial
- cuerpo completo recortado
- interacción cercana con el dispositivo
- interacción distante con pantalla

Evitar repetir siempre “dios a la derecha + texto a la izquierda”.

---

# 6. Dispositivos

Todo dispositivo debe verse **realista y fabricable**.

### Materiales permitidos
- aluminio
- vidrio
- policarbonato mate
- metal anodizado
- superficies negras o grises

### Reglas
- escala realista
- grosor realista
- biseles correctos
- cámaras / puertos plausibles
- teclado, bisagra y pantalla proporcionados
- reflejos controlados
- nada futurista imposible

### Branding del hardware
Cuando el dispositivo muestre marca:

- usar únicamente el **isotipo oficial EFESTUM**
- pequeño
- centrado o en posición plausible de fabricante
- sin inventar logotipos

# 8. Sistema de composición

La composición debe variar de una pieza a otra.

## Layout A — Texto izquierda / dios derecha
- Logo horizontal arriba izquierda
- Titular dominante izquierda
- Dios 3/4 derecha
- Dispositivo a la altura del torso
- CTA inferior

## Layout B — Dios izquierda / texto derecha
- Dios ocupa 40–50%
- Texto en columna derecha
- Logo arriba derecha o centrado
- UI pequeña como apoyo

## Layout C — Titular superior / escena inferior
- Gran titular arriba
- Dios + dispositivo abajo
- Mucho espacio negativo
- Ideal para frases cortas

## Layout D — Dios central
- Dios centrado
- Titular partido arriba y abajo
- Sistema visual muy editorial
- Evitar demasiados bullets

## Layout E — Split vertical
- 50% escultura
- 50% interfaz / dashboard
- Titular cruza parcialmente el eje
- Útil para integración o analítica

## Layout F — Dispositivo protagonista
- Laptop/tablet ocupa 45–55%
- Dios en segundo plano
- Titular pequeño pero contundente
- Ideal para software o dashboards

## Layout G — Close-up
- Rostro escultórico en primer plano
- Dispositivo recortado
- Titular corto
- Mucho espacio blanco

## Layout H — Escena de escritorio
- Dios sentado usando laptop
- Composición corporativa
- Sin objetos innecesarios
- Ideal para “Construimos lo que no existe”

**Regla:** no repetir el mismo layout en piezas consecutivas.

# 9. Sistema de copy

## Fórmula principal

### Label
2–5 palabras.

Ejemplos:
- INTEGRACIÓN TOTAL
- INTELIGENCIA ARTIFICIAL
- AUTOMATIZACIÓN
- GOBIERNO DE DATOS
- ARQUITECTURA DE SOFTWARE

### Headline
Máximo recomendado: **8 palabras**.

Debe:
- afirmar
- ser directo
- evitar preguntas
- evitar clichés
- sonar a ingeniería

### Supporting line
Una sola línea o dos líneas cortas.

Debe aterrizar el mensaje en algo real:

- operación
- datos
- integración
- software
- automatización
- infraestructura
- observabilidad

### Cierre
`efestum.com`

# 15. Regla editorial del feed

Aunque este skill produce piezas con dioses, EFESTUM no debe convertirse en una marca “de mitología”.

Recomendación:

> **Máximo 1 publicación mitológica por cada 4 publicaciones del feed.**

Las otras piezas deben usar:

- dashboards
- dispositivos
- arquitectura de sistemas
- interfaces
- procesos
- software
- escenas de trabajo

La mitología es una **firma de campaña**, no el tema permanente de la marca.
