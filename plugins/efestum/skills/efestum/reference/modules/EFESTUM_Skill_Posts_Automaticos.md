# EFESTUM — Skill para generar posts automáticos

## Objetivo
Generar piezas de redes sociales coherentes con la identidad visual y verbal de EFESTUM. La imagen debe sentirse como ingeniería de software premium: blanca, precisa, sobria y contemporánea. Nunca debe parecer una pieza genérica de IA, cyberpunk o tecnología gamer.

## Rol de la skill
Crear posts 4:5 para redes sociales que comuniquen una sola idea por pieza. La composición puede variar ampliamente, pero el sistema visual debe mantenerse reconocible.

---

## 1. Identidad visual obligatoria

### Paleta
- Fondo principal: blanco / papel #FFFFFF o #F4F4F4.
- Tinta principal: #0A0A0A.
- Rojo de acento: #E60004.
- Grises auxiliares: #8A8A8A, #D8D8D8, #262626.
- El rojo es señal, no relleno: idealmente <5% del área visual.
- No introducir colores ajenos.

### Mármol Digital
- Fondo blanco con textura técnica muy tenue.
- Usar campos de puntos, microtramas, líneas de construcción, coordenadas, nodos o retícula técnica muy sutil.
- NO usar vetas reales de mármol, piedra envejecida, grecas, columnas decorativas, laureles ni ornamento clásico.
- El fondo debe respirar; el espacio negativo es parte del diseño.

### Filo de forja
- Línea horizontal roja delgada como firma visual.
- Puede aparecer bajo el título, como separador o acento corto.
- Nunca convertirla en marco completo ni elemento ornamental dominante.

### Logotipo
- Priorizar siempre el logo horizontal de EFESTUM.
- Usar el archivo maestro proporcionado; no redibujar, deformar, rotar, comprimir ni reinterpretar.
- Sobre fondo blanco usar versión negra.
- No añadir “SYSTEMS” salvo que el archivo oficial utilizado lo incluya de origen.
- Mantener zona de seguridad alrededor del logo.

---

## 2. Tipografía

### Títulos
- Usar siempre la tipografía propietaria / estilo tipográfico del logotipo EFESTUM.
- Sensación: geométrica, tecnológica, abierta, de esquinas suaves y construcción modular.
- No sustituir por serif, grotesca condensada, display agresiva o tipografía gamer.

### Textos secundarios
- Usar Rubik.
- Rubik Regular para cuerpo.
- Rubik Bold/Semibold para etiquetas o énfasis.
- Etiquetas: mayúsculas con tracking amplio.

### Jerarquía
- Un título dominante por pieza.
- Máximo dos tamaños de display por superficie.
- Cuerpo breve: 1–3 líneas cuando sea necesario.
- El texto debe rematar la imagen, no explicarla en exceso.

---

## 3. Composición

### Formato recomendado
- 1080 × 1350 px (4:5).
- Adaptable a 1080 × 1080 y 1080 × 1920 manteniendo proporciones y reacomodando, nunca estirando.

### Variación obligatoria
No repetir siempre la misma plantilla. Alternar entre:
1. Objeto dominante a la derecha + texto a la izquierda.
2. Objeto dominante a la izquierda + texto a la derecha.
3. Composición centrada y simétrica.
4. Título superior + visual técnico inferior.
5. Título lateral vertical + dashboard central.
6. Visual isométrico / arquitectura de sistema + copy corto.
7. Layout editorial con gran espacio negativo.
8. Dispositivo a media altura con interfaces flotantes discretas.

### Densidad
- Una sola idea principal por pieza.
- No saturar con iconos.
- Si hay iconos, usar máximo 3 y con función informativa.
- El vacío debe ocupar una parte importante de la composición.

---

## 4. Lenguaje visual para piezas sin dioses

Usar únicamente elementos tecnológicos contemporáneos, realistas y sobrios:
- laptops
- monitores
- tablets
- teléfonos móviles
- dashboards
- interfaces de ERP / CRM
- diagramas de integración
- capas de arquitectura
- flujos de automatización
- visualización de datos
- nodos / conexiones
- módulos de software

### Regla de dispositivo
- Todo dispositivo debe tener materiales y texturas fotorrealistas: aluminio, vidrio, plástico mate, pantalla realista.
- El isotipo de EFESTUM debe aparecer discretamente en el dispositivo cuando sea visible.
- No usar marcas de terceros.
- No usar robots humanoides, cerebros de neón, hologramas arcoíris, circuitos literales decorativos ni UI gamer.

### Interfaces
- UI limpia, ejecutiva y creíble.
- Fondo claro o panel oscuro neutro con acentos rojos mínimos.
- Evitar cifras no verificadas.
- Si una cifra es ilustrativa, marcarla internamente como placeholder y no publicarla sin validación.

---

## 5. Sistema verbal

### Tono
- Preciso.
- Sobrio.
- Ambicioso sin exageración.
- Ingeniería, no hype.

### Verbos preferidos
forjar, construir, diseñar, integrar, automatizar, escalar, conectar, ordenar.

### Evitar
líder, innovador, disruptivo, vanguardia, última generación, revolución, transformación digital, sinergia, ecosistema, empoderar, “soluciones a tu medida” genéricas, exclamaciones.

### Estructura de copy
- Headline: idealmente 2–8 palabras.
- Subline: una frase concreta opcional.
- Cierre: efestum.com.

### Copys sugeridos
- FORJAMOS SISTEMAS INTELIGENTES
- CONSTRUIMOS LO QUE NO EXISTE
- TU OPERACIÓN, SIN PUNTOS CIEGOS
- UNA SOLA FUENTE DE VERDAD
- CONECTAMOS LO QUE YA TIENES
- MENOS PASOS. MÁS CONTROL.
- DATOS QUE SÍ TRABAJAN
- SOFTWARE QUE SIGUE TU OPERACIÓN
- INTEGRACIÓN SIN ISLAS
- AUTOMATIZAR ES QUITAR FRICCIÓN
- ARQUITECTURA PARA CRECER
- EL SISTEMA DETRÁS DE LA OPERACIÓN
- DE PROCESOS SUELTOS A UN SOLO SISTEMA
- DECISIONES CON DATOS, NO SUPOSICIONES
- LO REPETITIVO NO DEBERÍA SER MANUAL

---

## 6. Checklist antes de entregar
- ¿El logo horizontal es fiel al archivo oficial?
- ¿El título usa el estilo tipográfico EFESTUM?
- ¿El cuerpo usa Rubik?
- ¿El rojo ocupa menos del 5%?
- ¿El fondo se siente blanco y técnico, no decorativo?
- ¿Hay una sola idea principal?
- ¿El layout difiere de la pieza anterior?
- ¿Los dispositivos se ven realistas?
- ¿El isotipo aparece correctamente en el hardware visible?
- ¿No hay cifras inventadas?
- ¿No hay buzzwords ni exclamaciones?
- ¿La pieza podría reconocerse como EFESTUM sin leer el logo?
